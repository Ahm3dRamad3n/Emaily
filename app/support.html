Frequently asked questions

Quick answers to the questions that come up most.

What is Emaily? +

Emaily is a form-to-email backend-as-a-service. It lets you receive form submissions — like contact forms — as emails without running your own mail server. You connect an email account you already own, design HTML templates with variable placeholders, and submit data through one public API endpoint. Emaily then queues, renders, secures, and delivers the email through your connected account.

How does email routing work? +

Your form or backend sends a request to /api/submit/{publicApiKey} with a template ID and the field values.

Emaily checks the request first — your project's access mode and allowed domains, reCAPTCHA or App Check if the template uses them, and rate limits. It then fills in the template's {{variables}}, validates the resulting HTML, and queues the email for background delivery through your connected service. Each submission is recorded with a status such as Pending, Sent, Failed, or Resent.

Which providers are supported? +
  • Gmail — connected through OAuth.
  • Microsoft Outlook — connected through OAuth.
  • SendGrid — connected with an API key.
  • Resend — connected with an API key.
  • Any SMTP account — connected with an app password.

After a successful send, Emaily can also post Telegram alerts, log to Google Sheets, and generate AI summaries.

What is the difference between publicApiKey and privateKey? +

Every project has a key pair. The publicApiKey (starts with pub_) goes in the request URL and identifies the project. The privateKey (starts with sec_) goes in the request body as privateKey and authorizes backend requests — keep it out of client-side code.

How they're used depends on the project's access mode:

  • FrontendOnly — the private key must not be sent; the request's Origin must match your allowed domains.
  • BackendOnly — the private key is required and must match.
  • Hybrid — treated as a backend call when a valid private key is present and there's no Origin; otherwise the frontend rules apply.
How do I configure OAuth? +

In your dashboard, add a sending service and choose the OAuth option, then pick Google or Microsoft. A popup opens with the provider's consent screen. Once you approve, the popup closes and hands the authorization back to Emaily.

Emaily requests send-only permission — gmail.send for Google and Mail.Send for Microsoft — never full mailbox access, and stores the resulting tokens encrypted. For a step-by-step walkthrough, see the documentation.

How can I inspect email logs? +

Open History in your dashboard and choose a project to see its submissions, each with a status. Opening a submission shows its details, and failed submissions offer a Retry send action.

One exception: if a template has Save to history switched off (privacy mode), its payload and rendered HTML are never stored, so those submissions can't be inspected in detail or retried.
