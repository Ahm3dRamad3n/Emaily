The problem

Every sending provider has its own credentials, quirks, and failure modes — and juggling more than one gets messy fast.

Emaily's answer

Connect Gmail, Outlook, SendGrid, Resend, or any SMTP account once. Emaily normalizes how you send, regardless of provider.

The problem

Public form endpoints are a magnet for spam, scraping, and abuse the moment they go live.

Emaily's answer

Per-template reCAPTCHA v2 with hostname matching, App Check JWT verification, rate limiting, and an escalating auto-ban system keep abusive traffic out automatically.

The problem

A failed send is usually a silent send — you find out from an annoyed customer, not your logs.

Emaily's answer

Every submission is recorded with status and error detail, and failed sends can be retried in one click from your dashboard.

The problem

Storing raw mail credentials next to your application code is a liability if that code ever leaks.

Emaily's answer

Connect through OAuth or an API key — every stored credential is encrypted at rest with AES-256-GCM.

Four steps, every time

01

Connect a service

Authorize Gmail or Outlook through OAuth, or add an API key (SendGrid, Resend) or SMTP app password.

02

Configure a project

Get a public/private key pair, write an HTML template with {{variables}}, and choose an access mode.

03

Submit

Your form or backend posts to /api/submit/{publicApiKey}. Emaily checks domain, CAPTCHA, App Check, and rate limits first.

04

Trace & retry

The send is queued, delivered, and logged with status — failures are visible and retryable, never silent.

More security than a contact-form backend usually gets

Nothing here is exaggerated — this is what actually runs behind every submission.

Encrypted credentials

AES-256-GCM authenticated encryption for every stored service credential.

Purpose-scoped JWTs

HS256 access tokens carry a dedicated login-purpose claim, so reset or verification tokens can never be reused as a session.

Short-lived sessions

10-minute access tokens, 7-day rotating refresh tokens, and immediate logout blacklisting.

Minimal-permission OAuth

Gmail uses only the gmail.send scope; Microsoft uses only Mail.Send — never full mailbox access.

Per-form bot protection

Optional reCAPTCHA v2 with hostname matching, plus App Check JWT verification with an optional expected issuer.

Dual-key access modes

FrontendOnly, BackendOnly, or Hybrid — you decide whether a public key alone is enough, or a private key is required.

Escalating auto-ban

Abusive IPs are banned automatically, escalating from 1 minute up to 30 days, logged with reason and endpoint.

HTML safety check

After variable substitution, every email body is validated by an HTML sanitizer — unsafe content is rejected before anything is sent.

Built for the backend you already have

No SDK to install. Point any form, or your own backend, at a project's public key and Emaily takes it from there.

publicApiKey lives in the URL and identifies the project. privateKey, when your access mode requires it, travels in the request body and proves the call came from your backend — never expose it in client-side code.
